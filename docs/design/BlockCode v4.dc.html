BlockCode

Learners drop in a CSV, snap blocks together and read the real code live. The same blocks export as SQL, Python or R, and errors link back to the block that caused them.

1
Blocks have no language

Data blocks normalise into one relational plan. The language toggle changes the code tab; the workspace stays put.

2
Pick columns, don't type

A dropped CSV becomes a source block in the toolbox. Its columns fill every dropdown.

3
Show where SQL ends

Python-only blocks are dashed. Using one turns off SQL and puts the reason on the block.

4
Two-way linking

Hovering a block highlights its lines and shows both forms. Clicking a problem highlights its block.

Block families
From enrolments
Source. Rounded "hat" block, nothing stacks above it. One per CSV or table.
Where · Group by
Data steps. SELECT, WHERE, JOIN, GROUP BY, HAVING, ORDER BY, LIMIT, new column. Compile to SQL and pandas.
grade > 50
Expressions. Round pills for slots: column, literal, compare, and/or/not, maths, is empty, in list, contains.
For each · Print
Python only. Variables, print, for, if/elif/else, while, lists. Can wrap a data pipeline.
Milestones that touch the UI
M3Python blocks: dashed style, per-block SQL warnings
M4Editor: toolbox, workspace, Code tab with SQL ⇄ Python toggle, dual-form tooltips
M5CSV drop overlay, inferred types, column dropdowns
M6Run, Output tab (table + stdout), Problems tab, error ↔ block
M7Save / load, Export .sql or .py (+ data)
Things the UI should point out
Empty values counted on drop "is empty" uses isna() Dates stay text in v1 No ORDER BY means no fixed row order
